# Techline Web

Витрина каталога спецтехники и админка. Next.js 16 (App Router), TypeScript
strict, Tailwind v4, shadcn/ui. Бэкенд — в соседней папке [`../backend`](../backend).

## Запуск

```bash
cp .env.example .env.local   # адрес бэкенда
npm install
npm run dev                  # http://localhost:3000
```

Бэкенд поднимается в своём репозитории командой `make compose` (слушает `:8000`).
Без него страницы открываются с понятной ошибкой, а не пустым экраном.

## Типы API генерируются из контракта

Руками типы для API не пишем: они выводятся из спецификации, поэтому изменение
контракта ломает компиляцию, а не рантайм. В репозитории лежит **снимок** —
`openapi/swagger.json`; генерация читает только его и потому воспроизводима.

Порядок обновления после изменений на бэкенде:

```bash
npm run sync:spec   # обновить снимок из репозитория бэкенда (только локально)
npm run gen:api     # перегенерировать src/lib/api/schema.d.ts
npm run build       # проверить, что фронт собирается по новому контракту
```

Оба файла коммитятся вместе. `npm run build` начинается с `check:api` и падает,
если типы разошлись со снимком. Путь к источнику — `CATALOG_SWAGGER_SOURCE`
(по умолчанию `../backend/swagger/swagger.json`); в CI `sync:spec` не запускается.

> **Важно.** Проверка сравнивает типы со снимком, а не с живым бэкендом:
> расхождение снимка с реальным API компиляцией **не ловится**.

## Где что лежит

| Путь                      | Что там                                                        |
| ------------------------- | -------------------------------------------------------------- |
| `src/app/`                | страницы и route handlers (маршрут = папка)                    |
| `src/app/(storefront)/`   | витрина; образец страницы — `catalog/[categorySlug]/`          |
| `src/lib/api/`            | клиент API: `server.ts`, `browser.ts`, `errors.ts`, `types.ts` |
| `src/lib/api/schema.d.ts` | сгенерированные типы, руками не править                        |
| `src/lib/auth/`           | cookie с токеном; внутрь токена смотрит только proxy.ts        |
| `src/lib/catalog/`        | чистые функции предметной области (например, сборка дерева)    |
| `src/components/ui/`      | компоненты shadcn/ui, свои сюда не добавляем                   |
| `src/components/states/`  | загрузка, пусто, ошибка — готовые компоненты                   |
| `src/proxy.ts`            | бывший middleware; закрывает `/admin/*`                        |
| `openapi/`, `scripts/`    | снимок контракта и команды генерации                           |

> **Цены в каталоге на стенде выдуманы.** Их проставляет импорт дампа
> (`dump/import/prices.mjs`), потому что на сайте-источнике цен нет вовсе,
> а без них не показать ни пересчёт в тенге, ни калькулятор лизинга,
> ни выпуск КП. Это не прайс и не коммерческое предложение; подробности
> и порядок наполнения — в `dump/README.md`.

## Соглашения

**Серверный или клиентский компонент.** По умолчанию — серверный: он выполняется
на сервере, ходит в бэкенд и присылает готовый HTML. `'use client'` добавляем
только когда нужен обработчик события (`onClick`), хук React (`useState`,
`useRouter`) или браузерное API. Правило одной фразой: _нужна реакция на действия
пользователя — клиентский, нужно только показать данные — серверный._
Клиентским делаем самый маленький кусок: на странице раздела это поля
фильтров и кнопка «Показать ещё», а не вся страница.

**Запросы к API.** Из серверных компонентов — `publicFetch` (открытые ручки)
или `serverFetch` (под авторизацией). Из клиентских — `browserFetch`: он идёт
через `/api/proxy`, потому что токен лежит в httpOnly cookie и браузеру не
виден. Путь, метод и тело проверяются по спеке, тип ответа выводится сам.

**Фильтры витрины — в адресе, не в `useState`.** Разбор и сборка адреса живут
в `src/lib/catalog/search-params.ts`; серверная страница читает `searchParams`,
клиентские компоненты только переписывают адрес через `router.push`.

**Витрина и админка устроены по-разному, и это осознанно.** На витрине
состояние живёт в адресе: ссылку отправляют, «назад» обязан работать, страницу
читает поисковик. В админке фильтры — состояние компонента: ссылкой на
отфильтрованный список никто не делится, а переключают их десятки раз подряд.
Первая страница данных в обоих случаях приходит с сервера.

**Кто вошёл — спрашиваем у бэкенда, а не выводим из токена.** `currentActor`
зовёт `GET /v1/auth/me`. Полезная нагрузка JWT — это строка, присланная
клиентом, а проверить подпись фронт не может; внутрь токена смотрит только
`proxy.ts` и только на срок действия.

**Страницы админки грузят данные через `loadAdminPage`.** Не ради красоты:
`redirect()` в Next.js бросает исключение, и обычный `try/catch` вокруг
загрузки проглотил бы переход на вход при истёкшем токене. Помощник
пропускает служебные исключения фреймворка сквозь себя.

**Ошибки и состояния.** `apiFetch` либо возвращает данные, либо бросает `ApiError`
(`kind`, `status`, `code`, `serverMessage`); страница ловит её и отдаёт
в `<ErrorState error={...} />` — текст подберётся сам. Пустой ответ —
`<EmptyState />`, загрузка — `loading.tsx`. Своих вариантов не пишем.
