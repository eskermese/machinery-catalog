# Дамп каталога techline.example

Снимок публичного каталога с сайта компании — данные и фотографии, сохранённые
для последующего переноса в этот сервис. Собран обходом карты сайта
`sitemap-store.xml` (612 адресов) плюс страницы разделов, которых в ней не было.

Сайт сделан на Tilda и отдаёт содержимое в HTML целиком, поэтому разбор идёт
по разметке — ни фида, ни API у него нет.

## Что где лежит

| Путь                   | Что это                                  |
| ---------------------- | ---------------------------------------- |
| `urls.txt`             | все обойдённые адреса                    |
| `pages/*.html.gz`      | исходные страницы как есть, сжатые       |
| `products.json`        | разобранные карточки                     |
| `listings.json`        | страницы разделов каталога — не товары   |
| `categories.json`      | категории с числом карточек              |
| `photos/*`             | фотографии товаров                       |
| `missing-sections.txt` | разделы, которых не было в карте товаров |

Страницы сохранены намеренно: разбор можно переделать по ним, не обходя сайт
заново. Все три шага повторно запускаемые — уже скачанное пропускается.

## Как собрано

```bash
node dump/fetch-pages.mjs    # шаг 1: страницы -> pages/
node dump/parse-pages.mjs    # шаг 2: разбор -> products.json, listings.json, categories.json
node dump/fetch-photos.mjs   # шаг 3: фотографии -> photos/, пути проставляются в products.json
```

Между запросами пауза: обходится чужой сервер, а не свой стенд.

Шаги 2 и 3 связаны в одну сторону: разбор перезаписывает `products.json`
целиком, и локальные пути фотографий в нём обнуляются. После повторного
разбора шаг 3 обязателен — иначе импорт заведёт карточки без единой
фотографии и не пожалуется («фотографий загружено: 0, отказов: 0»).
Скачивать заново он при этом не будет: файлы уже в `photos/`, и шаг только
проставляет пути.

## Формат карточки

```json
{
  "sourceUrl": "https://techline.example/avtokran-xct25l4_s",
  "slug": "avtokran-xct25l4_s",
  "title": "Автокран XCT25L4_S",
  "categorySlugs": [],
  "categoryNames": ["Автокраны"],
  "category": "Автокраны",
  "summary": ["Грузоподъемность: 25 000 кг."],
  "specs": [{ "name": "Грузоподъемность", "unit": "кг.", "value": "25 000", "numeric": true }],
  "photos": [
    { "sourceUrl": "https://static.tildacdn.pro/…png", "file": "photos/…png", "bytes": 547050 }
  ]
}
```

Категория берётся из двух источников, и это не дублирование. У товаров
с плоским адресом иерархию несут хлебные крошки; у вложенных (`/раздел/подраздел/товар`)
крошек нет вовсе, зато иерархия и есть сам путь. Сохранены оба вида — слаги
и человеческие названия.

Фотографии товара отделены от оформления сайта по частоте: логотипы, иконки
разделов и подложки повторяются на большинстве страниц, снимок техники — нет.

## Что в дампе неровно

Это снимок источника как есть, без причёсывания: решать, как приводить его
к своей схеме, лучше при переносе, а не при сборе.

- **Категории повторяются в разных написаниях.** «Башенные краны» и «Башенный
  кран» — одно и то же; подразделы автокранов по грузоподъёмности («от 25 до 55
  тонн») лежат наравне с самими «Автокранами».
- **У части карточек нет характеристик.** Примерно у каждой шестой таблицы
  на странице просто нет.
- **Значения характеристик не всегда числа.** Около трети — строки вида
  `34+8,2 (гусек)`, `≥80`, `1400R20`, `8JS118TB-B`. Числовой характеристикой
  такие не завести: тип в нашей схеме задаётся на всю категорию, и достаточно
  одного нечислового значения, чтобы вся характеристика стала строковой.
- **Названия характеристик не унифицированы.** «Номинальная грузоподъемность»,
  «Номинальная нагрузка» и «Грузоподъемность» встречаются как разные
  характеристики, хотя означают одно.
- **Цен на сайте нет вовсе** — там модель «оставить заявку». Ни у одной карточки
  цены не нашлось.
- **Бренд и модель отдельными полями не выделены**, только в названии
  («Погрузчик XCMG LW300FN»), и не везде («Автокран XCT25L4_S» — бренд только
  в адресе раздела).
- **Три адреса из карты сайта отвечают 404** (`afaltnye-zavody`,
  `dvuhosny-karerny-samosval-xde400`, `mikserg10v`) — это битые ссылки самого
  сайта, а не ошибка обхода. Товары, лежавшие под ними, получили категорию
  «404 Page Not Found.».

## Чего в дампе нет

Слаги сайта не годятся для наших адресов как есть: в них встречаются
подчёркивания и заглавные буквы (`avtokran-xct25l4_s`, `pogruzchik-xcmg-XC948-EV`),
а схема требует `^[a-z0-9]+(-[a-z0-9]+)*$`. Преобразование — шаг переноса,
в дампе слаги сохранены исходные.

## Цены в каталоге ВЫДУМАНЫ

**Цены, которые проставляет импорт, — демонстрационные. Это не прайс
и не коммерческое предложение.**

На сайте-источнике цен нет ни у одной карточки: там модель «оставить заявку».
Но вокруг цены построено всё остальное — пересчёт в тенге, фильтр и сортировка
по цене, калькулятор лизинга, выпуск коммерческого предложения, — и без цен
эти возможности показать не на чем.

Поэтому `dump/import/prices.mjs` расставляет правдоподобные значения: диапазон
задан по подразделу под порядок величин рынка новой китайской техники, а место
машины внутри диапазона выводится из её массы или мощности. Часть карточек
(каждая двадцать пятая) намеренно остаётся без цены — «цена по запросу» это
законный сценарий, и его тоже надо видеть.

Настоящие цены заводит менеджер в админке. **Повторный импорт затрёт их
демонстрационными** — перед запуском на наполненной базе это надо понимать.

То же относится к `dump/import/stand-data.sql`: курс валюты там — порядок
величины, а не котировка на сегодня, программы лизинга придуманы
и партнёров не называют.

## Перенос в каталог

```bash
docker exec -i techline-postgres psql -U postgres -d techline -f - < dump/import/wipe.sql
node dump/import/check.mjs    # справочник разделов: слаги и охват дампа
node dump/import/import.mjs   # категории -> характеристики -> фотографии -> карточки
docker exec -i techline-postgres psql -U postgres -d techline -f - < dump/import/stand-data.sql
```

Последний шаг заводит курс валюты, программы лизинга и кривые остаточной
стоимости: в дампе их нет, а без них не работают ни цена в тенге, ни
калькулятор, ни расчёт стоимости владения.

Казахские и английские названия импорт оставляет ПУСТЫМИ. Переводов
в источнике нет, а заглушка вместо перевода хуже пустоты: витрина
не отличит её от настоящего названия и покажет английскому читателю
слаг раздела или русское название карточки. Пустое поле она читает как
«перевода нет» и честно откатывается на русское.

Стенд, наполненный до этой правки, несёт заглушки: там казахское название
дублирует русское, а английское у разделов — слаг, у характеристик — код.
Лечится повторным прогоном всех трёх команд выше.

## Величины стоимости владения

Расхода топлива и интервалов ТО в источнике практически нет, и восполнить
их разбором нельзя. Проверено по всем 616 сохранённым страницам, не только
по `products.json`:

| Что есть в источнике               | Карточек | Годится для расчёта                    |
| ---------------------------------- | -------- | -------------------------------------- |
| «Объём/ёмкость топливного бака, л» | 76       | нет: это ёмкость, а не расход          |
| «Расход топлива на 100 км, л»      | 7        | нет: расход на пробег, а не на моточас |
| «Удельный расход, г/кВт·ч»         | 3        | нет: только через плотность и загрузку |
| **«Расход топлива, л/час»**        | **1**    | **да, переносится импортом**           |
| Интервал или стоимость ТО          | **0**    | —                                      |

Импорт переносит расход, только если источник назвал его в литрах на час
работы (см. `fuelConsumptionOf` в `import.mjs`). Остальное не переносится
намеренно: расход, выведенный из пробега или из предполагаемой загрузки
двигателя, даёт расчёт, который выглядит расчётом и является выдумкой,
а это хуже отсутствия расчёта — пустую строку на витрине видно, неверную
цифру нет.

Остальное заводится руками, по паспортам и прайсу сервисной службы.
Для этого есть `tco-fill.mjs`:

```bash
node dump/import/tco-fill.mjs --template ekskavator  # собрать таблицу по разделу
# заполнить dump/import/tco-values.csv руками
node dump/import/tco-fill.mjs                        # проверить, ничего не меняя
node dump/import/tco-fill.mjs --apply                # записать
```

Без `--apply` скрипт ничего не пишет: величины уходят на витрину и участвуют
в расчёте, который клиент читает как факт, и посмотреть, что именно уедет,
надо до записи. Непонятное значение («около 30», дробный интервал) — отказ
всего прогона, а не пропуск строки: наполовину заполненная таблица это
опечатка, и разбираться с ней надо до записи.

Пустая клетка означает «не заведено» и строку не трогает — так и надо
оставлять, если в паспорте величины нет. **Стереть уже заведённое значение
скрипт не умеет**: для этого есть форма карточки в админке.

Чего в паспортах ждать стоит, а чего нет:

- **интервал ТО** — есть; в брошюре XCMG XE215D прямо сказано «500h
  maintenance period», причём базовые 250 ч удваиваются до 500 ч на фирменном
  масле. Какой из двух брать — решение компании, а не факт из паспорта;
- **расход топлива л/мч** — как правило НЕТ. В брошюрах указывают ёмкость
  топливного бака, а не расход: он зависит от режима и нагрузки, и завод его
  не декларирует. Источник тут — собственные замеры или данные сервиса;
- **стоимость ТО** — в паспорте её нет и быть не может: это прайс сервисной
  службы, свой на каждом рынке.

`wipe.sql` чистит каталог и заявки, но не пользователей: администратор заводится
из конфигурации, а имена менеджеров проставлены руками. `import.mjs` не
дописывает к существующему каталогу — он рассчитан на пустой, поэтому перед
повторным запуском нужен `wipe.sql`, иначе слаги и коды столкнутся.

Порядок шагов внутри `import.mjs` обязателен: характеристика принадлежит
категории, значение — характеристике, а фотография должна лежать в хранилище
до того, как на неё сошлётся карточка.

Правила сведения — в шапках `taxonomy.mjs` и `specs.mjs`, там же таблица
синонимов. Коротко: раздел определяется по названию товара, а не по категории
источника (она на сайте местами неверна); характеристика заводится, если
встречается не меньше чем у двух машин подраздела, остальные значения уходят
в описание карточки; фильтруемой становится числовая характеристика не реже
чем у пяти машин.
