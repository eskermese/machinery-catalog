# Techline — состояние проекта

Каталог спецтехники с витриной, админкой и коммерческими предложениями.
Документ описывает то, что **уже реализовано**, и решения, из которых это
устройство выросло. Он написан для того, кто видит проект впервые.

**Два репозитория:**

| Репозиторий    | Что это                                 |
| -------------- | --------------------------------------- |
| `techline`     | Бэкенд на Go: API, база, миграции       |
| `techline-web` | Next.js: витрина, админка, публичное КП |

Заказчик (в портфолио обезличен, «ТехЛайн» — вымышленное название) — дилер спецтехники в Алматы (в основном XCMG),
запасные части, сервис. Релиза не было; миграции правятся исходные,
а не дописываются новыми.

## 2. Бэкенд

### Стек

Go, chi, pgx/v5, PostgreSQL 17, Dragonfly (кэш, протокол Redis), gomock,
swaggo, shopspring/decimal, resty. **Новых зависимостей в go.mod не добавляют.**

### Слои

```
entity  →  service  →  storage/repository  →  transport/http
```

Порты объявляются там, где потребляются: `service.RateProvider`,
`repository.*Repository`. Сущности не знают ни про базу, ни про HTTP.

### Сущности

`catalog` (категория, характеристика, вариант, карточка, значение, фото),
`catalog_search` (фильтр, курсор, страница), `search_query` (варианты
запроса), `user`, `lead`, `quote`, `leasing_program`, `residual`, `fx`,
`media`, `audit`, `event`.

### Таблицы

`users`, `categories`, `attributes`, `attribute_options`, `machines`,
`machine_attribute_values`, `machine_images`, `leads`, `quotes`,
`leasing_programs`, `residual_value_curves`, `fx_rates`, `fx_markups`,
`notification_outbox`.

### Ручки

41 путь: 13 публичных, 28 админских. Контракт описан swaggo и лежит
в `swagger/`; фронт держит его снимок и проверяет соответствие.

### Что стоит знать про реализацию

**Поиск полнотекстовый.** `to_tsvector('russian', search_text)` с префиксным
`:*`, ранжирование `ts_rank`. Запасной путь — триграммы (`pg_trgm`):
`word_similarity` для опечаток и `ILIKE '%…%'` для подстроки. `search_text` —
генерируемый столбец, склейка названий на трёх языках, бренда и модели;
два индекса, GIN по обоим путям. Ранжирование уживается с keyset-пагинацией
через целочисленный ключ релевантности в курсоре.

**Пагинация курсорная**, номер порции наружу не выходит — витрина хранит
в адресе номер, а курсоры собирает сама.

**Валюта прайса — юань.** Цена хранится ровно одна, в `price_cny_cents`;
тенге и доллары ВЫВОДЯТСЯ из неё, каждый по своей паре и своей наценке.
Второго хранимого прайса нет. Валюты объявлены в домене
(`entity.CurrencyCNY/KZT/USD`), а не в конфигурации: настройкой пара воркера
могла бы разойтись с парой расчёта.

**Курс** берётся по правилу «ручной курс на дату → курс Нацбанка на ту же дату
→ нет курса». Правило живёт одним местом — в сортировке выборки последнего
курса. Ручные курсы заводит менеджер из админки, курсы Нацбанка тянет воркер.
Пары CNY→USD Нацбанк не публикует: она выводится кросс-курсом через тенге,
и наценка применяется РОВНО ОДИН РАЗ — из строки наценки самой пары.

Курса нет — цена показывается только в юанях, блок стоимости владения
скрывается, ручки расчёта отвечают отказом. Демонстрационного курса
в стенде намеренно нет.

**Доллар — необязательное второе отображение.** Включается настройкой
`show_usd_price` в таблице `app_settings` из админки, участвует только
в показе цены на витрине: ни лизинг, ни стоимость владения, ни коммерческое
предложение его не используют.

**Наценки** (`fx_markups`) свои у каждой пары, история сохраняется,
действующая — с максимальным `effective_from` не в будущем. Правит их
администратор; вводить курс может менеджер.

**Стоимость владения** считается на сервере: решение «показывать ли блок»
зависит от того, скольких величин не хватает, а узнать это можно только
у ручки. Не хватает больше половины — блок не показывается вовсе.

**Границы значений характеристик** приходят вместе со списком характеристик
раздела: из них витрина строит подсказку «в разделе от 138 до 310 кН».
Считаются одним запросом по опубликованным карточкам поддерева.

## 3. Фронтенд

### Стек

Next.js 16 (App Router, Turbopack), TypeScript strict, Tailwind v4,
shadcn/ui поверх `radix-ui`, lucide, next-themes, sonner.
**Новых зависимостей в package.json не добавляют**; компоненты берутся
из shadcn/ui, свои не пишутся там, где есть готовые.

### Правило номер один: состояние живёт в адресе

Фильтры, сортировка, запрос поиска, номер показанной порции, набор
к сравнению — всё в URL. Отсюда следует: ссылкой можно поделиться, кнопка
«назад» работает сама, а серверный рендер отдаёт готовую страницу.

### Маршруты

```
/[lang]/                       главная
/[lang]/catalog/[раздел]       каталог раздела
/[lang]/catalog/[раздел]/[слаг] карточка машины
/[lang]/search                 результаты поиска
/[lang]/compare                сравнение
/[lang]/leasing /service /spare-parts /about /contacts
/admin/...                     админка (без языка)
/login                         вход (без языка)
/quote/[token]                 публичное КП (без языка)
```

### Контракт с бэкендом

Снимок OpenAPI лежит в `openapi/swagger.json`, типы генерируются из него
в `src/lib/api/schema.d.ts`. Конвейер: `npm run sync:spec` → `gen:api` →
`check:api`. Последнее входит в `npm run build`, поэтому расхождение
контракта роняет сборку, а не выясняется в бою.

Браузер ходит в бэкенд только через `/api/proxy/...`: токен лежит
в httpOnly cookie, и подставить `Authorization` в браузере нечем.

### Многоязычность

Три языка: `ru` (по умолчанию), `en`, `kk`. Подробности — в отчёте
`tasks_results/2026-08-31-10-40-00-i18n.md`. Коротко:

- Витрина целиком под сегментом `[lang]`, адреса с префиксом, корень уводит
  на `/ru`. Админка, вход и КП — без префикса и на русском.
- Язык определяется в `src/proxy.ts` (в Next.js 16 это переименованный
  middleware) и уезжает заголовком в корневую раскладку, где стоит `<html lang>`.
- Словарь: русский — источник правды, тип формы выводится из него, остальные
  языки обязаны повторить каждый ключ, иначе ошибка сборки.
- Строки с подстановкой — **функции**, а не шаблоны: склонение остаётся
  внутри языка. В русском три счётные формы, в английском две,
  в казахском ни одной.
- Названия данных (разделы, характеристики, карточки) переводятся в базе;
  пустое поле означает «перевода нет», и витрина откатывается на русское.
- Переводы каталога лежат в `dump/i18n/` глоссарием, ключ — русская строка.

### Оформление

Фирменный цвет — янтарный, только на действии (главные кнопки, выбранное,
наличие, фокус). Фон и текст нейтральные. Тёмная тема есть, по умолчанию
светлая, настройка ОС не учитывается. Подложка под фотографиями светлая
в обеих темах: снимки сняты на белом.

## 4. Инфраструктура и запуск

```bash
# бэкенд
cd techline && make compose && make migrate-up

# фронт
cd techline-web && npm run dev        # или npm run build && npm run start
```

Compose поднимает postgres, dragonfly, pyroscope, prometheus и сам сервис.
API — `localhost:8000/api`, витрина — `localhost:3000`.

### Наполнение стенда

```bash
docker exec -i techline-postgres psql -U postgres -d techline -f - < dump/import/wipe.sql
node dump/import/check.mjs
node dump/import/import.mjs
docker exec -i techline-postgres psql -U postgres -d techline -f - < dump/import/stand-data.sql
node dump/i18n/build-sql.mjs
docker exec -i techline-postgres psql -U postgres -d techline -f - < dump/i18n/translations.sql
docker exec techline-cache redis-cli FLUSHALL
```

**Кэш обязателен к сбросу** после правок в базе мимо API: иначе ручки
отдают прежние данные.

### Проверки

| Бэкенд                          | Фронт                  |
| ------------------------------- | ---------------------- |
| `go build ./...`                | `npm run typecheck`    |
| `make lint`, `go vet ./...`     | `npm run lint`         |
| `make test`                     | `npm run format:check` |
| `make all`, `make swag`         | `npm run build`        |
| `make integration` (dockertest) | `npm run check:api`    |

`make integration` **сносит compose-стек целиком** по завершении: стенд после
него надо поднимать заново.

## 5. Известные ограничения

Их важно знать до того, как принимать решения.

### Аутентификация

Входа по паролю нет: токен выдаётся по номеру телефона, подтверждения
владения номером не существует. Администратор входит, только если заведён
в `ADMIN_PHONES`. Менеджер — по настройке `AUTH_SELF_REGISTRATION`:
при включённой (умолчание) учётная запись создаётся первым входом, то есть
пускает любой номер; при выключенной входит только заведённый.

**Ручки «завести сотрудника» в API нет.** Единственный способ появиться
в системе — самостоятельная регистрация. Поэтому выключать её нужно там,
где сервис доступен снаружи, и нельзя выключать глухо.

`JWT_SECRET` на стенде — дефолтный `local-jwt-secret`.

### Данные

- **Перевода названий на казахский и английский нет у части характеристик**
  (26 из 610): их русский оригинал сломан машинным переводом источника
  («Дать процесс», «Гидравлический банк»). Список — в `dump/i18n/glossary.json`
  под ключом `_suspect`, чинить надо по-русски.
- **Расход топлива и интервалы ТО** заполнены только у экскаваторов;
  без них блок стоимости владения не показывается. На стенде он не выходит
  ни у одной карточки.
- **Срок поставки** не заполнен ни у одной из 456 карточек.
- **Наличие**: все 456 машин «под заказ», «в наличии» нет ни одной.
- **Фотографий больше одной** нет ни у одной карточки: миниатюры галереи
  на стенде не появляются.
- **Единица измерения** у характеристик типа `string` вшита в значение
  («33 500 кг»), а столбец `unit` пуст. Такие значения на других языках
  остаются с русской единицей.
- Цены **демонстрационные**: на сайте-источнике их нет.

### Поиск

Индекс построен как `to_tsvector('russian', …)` и чужой морфологии не знает.
Английские и казахские названия станут искомыми, но «excavators» не найдёт
«excavator», а казахские окончания русский стеммер не отрежет. Готовой
казахской конфигурации в стандартной поставке Postgres нет; запасным путём
остаётся уже построенный триграммный индекс.

## 6. Соглашения, которые действуют всегда

- `internal/domain/leasing` и `internal/domain/tco` не трогать.
- Новых зависимостей не добавлять — ни в `go.mod`, ни в `package.json`.
  Расширения Postgres можно, если они в стандартной поставке образа.
- Миграции править исходные: релиза не было.
- Коммитить по одному изменению.
- Недостающие данные не выдумывать: выдуманный расход топлива даёт расчёт,
  выглядящий расчётом, а являющийся догадкой.
- Свои UI-компоненты не писать там, где есть готовые в shadcn/ui.
- Никаких `Co-Authored-By` в сообщениях коммитов.
